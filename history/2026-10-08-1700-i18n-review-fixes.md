# 2026-10-08 17:00 - i18n review fixes, after rebasing onto 0.4.0

## Goal

Close what review of PR #28 found once it was rebased onto 0.4.0.

## Findings and changes

- **The documented way to change one English word did not work.** `senren:install` copied
  `config/locales/senren.en.yml`. Rails loads `config/locales` in name order, so that file loaded after the host's
  `en.yml` and won: with both present, `senren.pagination.next: "Newer"` in `en.yml` still rendered "Next". The copy
  also pinned the wording, so a default improved in a later release never reached the app. The install now copies no
  locale file by default; every locale, English included, is asked for by name (`--locales`, `senren:locales en`).
  The docs say what a copied `senren.en.yml` does.
- **`senren:install --force` replaced the host's edited translations.** `--force` is the flag for refreshing
  Senren-managed files, and a locale file stops being one when it is copied. The generator now has
  `--force-locales` for that, and `--force` leaves translations alone. `senren:locales <name> --force` is unchanged,
  since it names the file it replaces.
- **A misspelt `%{variable}` in a host translation was a 500.** `senren_t` rescues
  `I18n::MissingInterpolationArgument` and interpolates the English default instead, in both the template and
  `BaseComponentPatch::TRANSLATION_HELPER` (pinned together by `test/i18n_catalog_test.rb`).

## Considered and left

- Guarding the Stimulus controllers against an absent value attribute. It only matters for a host that copied a new
  controller beside an old component. For the status regions the guard changes nothing (they start empty, so writing
  `""` announces nothing either way); for the theme toggle it would leave a stale label that names the wrong theme,
  which is worse than a blank one. The CHANGELOG already says to copy the component and controller together.
