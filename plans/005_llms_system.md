# Plan 005 — llms.txt System

## Purpose

Define the generation, structure, and update flow for
`public/llms.txt` and `public/llms-full.txt`, the AI-discoverable
descriptions of the host app's Senren installation.

## Scope

- `public/llms.txt`
- `public/llms-full.txt`
- `Senren::Rails::LlmsWriter`
- `senren:llms:generate` rake task
- Templates `docs/llms_template.md` and a full template.

## Decisions

1. `llms.txt` is the **short** pointer file. Target size: under 4 KB.
   It points AI agents to `.senren/skill.md` and lists hard rules.
2. `llms-full.txt` is the **full** snapshot. It includes the entire
   skill.md content plus conventions, recipes, and an inventory of
   installed components. Target size: bounded by content, not capped.
3. Both files are fully regenerated on every `senren:add`,
   `senren:skill:sync`, and `senren:llms:generate`. They are not
   user-edited; the entire file is owned by `LlmsWriter`.
4. Header of every generated file includes a "do not edit" notice and
   a pointer to the source of truth.
5. URLs inside llms files are repo-relative paths, never absolute
   external URLs (the host app may be private).

## Files to create

```
senren-rails/lib/senren/rails/llms_writer.rb
senren-rails/docs/llms_template.md
senren-rails/lib/generators/senren/install/templates/llms.txt.tt
senren-rails/lib/generators/senren/install/templates/llms-full.txt.tt
senren-rails/test/components/llms_writer_test.rb
```

## Files to modify

- `lib/tasks/senren.rake` (add `senren:llms:generate`).

## Expected behavior

- `senren:install` writes both files immediately, even before any
  components are added, so AI agents can discover Senren on day one.
- Each `senren:add` regenerates both files atomically (write to temp,
  rename) to avoid AI agents reading half-written files.
- `llms.txt` content order is stable: header → rules → important
  files → installed component summary → footer.

## Test strategy

- Snapshot tests for empty install and Phase 1 install.
- Stability test: regenerate twice, assert byte-identical output for
  identical input.
- Atomicity test: simulate write failure mid-render and assert
  original file is intact.

## Acceptance criteria

- [ ] Both files generated by `senren:install`.
- [ ] Both files regenerated by `senren:add` and `senren:skill:sync`.
- [ ] `llms.txt` under 4 KB for full Phase 1 install.
- [ ] Stable ordering across runs.
- [ ] Header marks files as generated.
