# Plan 002 — Generator Design

## Purpose

Define the behavior, options, and file outputs of every Senren
generator and rake task that writes to the host app filesystem.

## Scope

- `senren:install` generator.
- `senren:component NAME [--no-client]` generator.
- `senren:add` rake task.
- `senren:skill:sync` rake task.
- `senren:llms:generate` rake task.
- `senren:doctor` rake task.

## Decisions

1. The component generator includes the Senren Stimulus structure by
   default. `--no-client` disables it for static-only custom
   components. `--client` remains accepted as the explicit positive
   flag and is shown in docs for interactive components so Stimulus
   does not look optional. `--include_client=true` is not supported.
2. All generators are idempotent: re-running them must not duplicate
   content; existing files are skipped unless `--force` is passed.
3. `senren:add` is a rake task, not a Rails generator, because it
   accepts a variable list of component names and reads the registry.
4. All generators write to predictable, documented paths only. They
   never edit files outside the documented set.
5. After any write, the affected generator must:
   - Update `.senren/installed_components.yml`.
   - Trigger `SkillWriter` to update `.senren/skill.md`.
   - Trigger `LlmsWriter` to regenerate `public/llms.txt` and
     `public/llms-full.txt`.

## Files to create (in host app)

`senren:install`:

```
.senren/skill.md
.senren/registry.yml
.senren/installed_components.yml
.senren/conventions.md
app/components/senren/base_component.rb
app/assets/stylesheets/senren.css
public/llms.txt
public/llms-full.txt
```

`senren:component NAME`:

```
app/components/senren/<name>_component.rb
app/components/senren/<name>_component.html.erb
app/javascript/controllers/senren/<name>_controller.js
test/components/senren/<name>_component_test.rb
test/system/senren/<name>_test.rb
```

`senren:component NAME --no-client`:

```
app/components/senren/<name>_component.rb
app/components/senren/<name>_component.html.erb
test/components/senren/<name>_component_test.rb
```

`senren:add NAME...`:

- Files declared in `registry/components.yml` for each component.
- Stimulus controllers if `client: true` (or `--client` override).
- Docs examples for `client: true` components must include `--client`
  explicitly.

## Files to modify (in host app)

- `.senren/installed_components.yml` (append, dedupe).
- `.senren/skill.md` (regenerated by `SkillWriter`).
- `public/llms.txt` and `public/llms-full.txt` (regenerated).

## Expected behavior

- Re-running `senren:install` does not destroy user edits to
  `.senren/skill.md`. Implementation: skill file has a generated
  region delimited by HTML comments; only that region is rewritten.
- `senren:component` always uses the gem's `templates/` directory as
  the source for file content; not hard-coded strings in the
  generator.
- `senren:add nonexistent_component` exits with a clear error and
  non-zero status; nothing is written.
- `senren:component NAME` creates the ViewComponent, matching test,
  Stimulus controller, and system test by default.
- `--no-client` skips the Stimulus controller and system test.

## Test strategy

- Generator tests under `test/generators/` invoking each generator
  against a temp host directory and asserting files + content.
- Idempotency tests: run twice, assert no duplicates and no diff on
  second run.
- Negative tests: invalid component name, missing registry entry,
  missing host app, conflicting file with `--no-force`.

## Acceptance criteria

- [ ] Every command from section 6 of `master_prompt.md` works.
- [ ] All generators are idempotent.
- [ ] All generators are covered by tests.
- [ ] `--no-client` is documented for static-only custom components.
- [ ] Errors are actionable (suggest valid component names on typo).
