# Translating Senren components

Every word a component shows or announces can be translated from your app's
locale files, without editing a component. That covers the visible labels
("Previous", "Next", "Close", "Today"), the `aria-label` and screen-reader text
("Toggle sidebar", "Go to slide 2"), the defaults for arguments such as
`label:` and `placeholder:`, the calendar's month and weekday names, and the
sentences a Stimulus controller writes into the page after it loads ("Copied",
"Slide 2 of 3").

## How it works

Each string goes through one helper, `senren_t`, with its English as the
default:

```ruby
senren_t('pagination.next', default: 'Next')
```

That is `I18n.t("senren.pagination.next", default: "Next")`. If your app defines
`senren.pagination.next` for the current locale it wins; if not, the English in
the component is used. Two things follow:

- **Nothing is required for English.** Install Senren, render a component, and it
  says what it always said. There is no locale file to forget.
- **A missing translation never raises**, not even with
  `config.i18n.raise_on_missing_translations = true`, because I18n only reports
  a key that has no default.

Keys are `senren.<component>.<key>`. `senren.shared.*` holds the few words that
are the same word in more than one component (`open`, `close`).

## Install the locale files

`senren:install` copies `config/locales/senren.en.yml` into your app. It lists
every key with its current English, so it is the thing to read, search and copy
from. A shipped translation is copied only when you ask for it:

```bash
bin/rails generate senren:install --locales en vi   # at install time
bin/rails senren:locales vi                         # any time later
bin/rails senren:locales vi --force                 # replace your copy with the shipped one
```

Today the gem ships `en` and `vi`. The files are yours once they are copied:
the installer never overwrites one that exists unless you pass `--force`, so a
re-run after a gem upgrade does not undo your wording.

A translation is only loaded when its file is in `config/locales`, and a locale
becomes known to I18n when a file for it is loaded. If your app builds a
language switcher from `I18n.available_locales`, copying `senren.vi.yml` is what
makes Vietnamese appear in it, which is why it is opt-in.

## Change one word

Edit the value in your copy, or define just that key in any locale file you
already have. You do not need to copy the whole file:

```yaml
# config/locales/en.yml
en:
  senren:
    pagination:
      next: "Newer"
      previous: "Older"
```

Everything you do not mention keeps its English.

## Add a language

1. Copy `config/locales/senren.en.yml` to `config/locales/senren.fr.yml`.
2. Change the top-level key from `en:` to `fr:`.
3. Translate the values.

```yaml
fr:
  senren:
    pagination:
      label: "Pagination"
      previous: "Précédent"
      next: "Suivant"
    cart:
      remove_item: "Retirer %{name}"
```

Keep every `%{name}` spelled exactly as it is. They are filled in when the
component renders, and a translation that names a variable the component does
not pass (a typo such as `%{nmae}`) raises when that component shows. You can
move a variable anywhere in the sentence, and leave one out if the sentence does
not need it. A key you delete falls back to English, so a partial translation is
a working translation.

Then select the locale the way your app already does, for example
`I18n.locale = :fr` in an `around_action`. A word you did not translate shows in
English, because the English is the default.

If you would like the language included in the gem, send the file in a pull
request: `templates/locales/senren.<locale>.yml`, with the same keys as
`senren.en.yml`. `test/i18n_catalog_test.rb` checks that the keys and the
`%{}` variables match.

## Text you pass in yourself

An argument you pass is used exactly as given and is never looked up:

```erb
<%= render Senren::PaginationComponent.new(label: "Pages", current_page: 2, total_pages: 5) %>
```

Only the argument you leave out gets the translated default. Two details:

- `label: nil` still means "no label". For an attribute such as `aria-label` that
  omits it, as it always has. Pass `""` for an empty string and leave the
  argument out for the default.
- Words that arrive as *data* are yours to supply: a column header built from the
  key `:created_at` ("Created at"), the items of a menu, the text in a slot. Give
  `TableComponent` and `DataTableComponent` a `label:` per column to control it.

Values you interpolate into a translation are text. A name containing `<b>`
shows as the characters `<b>`, not as an element.

## What a controller says

Five controllers write a sentence into the page after it loads. They no longer
carry the English in JavaScript: the component renders each one into a Stimulus
value, and the controller reads it.

| Controller | Value | Key |
| --- | --- | --- |
| `clipboard` | `copied-status` | `senren.clipboard.copied_status` |
| `api_key_field` | `copied-status` | `senren.api_key_field.copied_status` |
| `carousel` | `status-template` | `senren.carousel.status` |
| `theme_toggle` | `light-label`, `dark-label` | `senren.theme_toggle.light`, `.dark` |
| `rich_text_editor_lite` | `link-prompt` | `senren.rich_text_editor_lite.link_prompt` |

The carousel's value is a template. Its `%{current}` and `%{total}` are left in
for the controller to fill in on every slide change, so a translation has to keep
them.

## Components you copied before this existed

`bin/rails senren:add <anything>` adds the `senren_t` helper to your
`app/components/senren/base_component.rb` if it is missing, so components you add
from now on work.

Components you copied earlier still have their English written into them. To
translate one, copy it again with `bin/rails senren:add pagination --force`
(which replaces any edits you made to that component), or change its strings by
hand. It is one call per string: swap `"Next"` for
`senren_t('pagination.next', default: 'Next')`. `senren.en.yml` lists the key for
every string.

## Writing a component or an edit that has text

Anything a person reads or a screen reader announces goes through `senren_t`
with a literal key and a literal English default:

```ruby
def initialize(label: senren_t('tabs.label', default: 'Tabs'), **html)
```

```erb
<button><%= senren_t('date_picker.today', default: 'Today') %></button>
<button aria-label="<%= senren_t('cart.remove_item', default: 'Remove %{name}', name: item[:name]) %>">
```

- Use the component's own namespace. Use `shared` only for a word that more than
  one component says.
- Put the English where the call is. Do not write it in a locale file first.
- Give an argument its default in the signature, as above. Ruby evaluates it
  when the component is built, in the locale that is current then.
- A string a controller needs goes to it as a Stimulus value, never as text in the
  JavaScript.
- Symbols that are not words (`×`, `+`, `*`) stay as they are.

If you are working on the gem itself, `bin/i18n-sync` regenerates
`templates/locales/senren.en.yml` from the calls, and `bin/i18n-sync --check`
reports whether it is current. `senren.vi.yml` is written by hand. The tests fail
if the two files disagree with the code or with each other, if a call is not
literal, and if a template shows a word that did not go through `senren_t`.
